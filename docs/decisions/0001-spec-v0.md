# Decision record 0001: specification version 0

Date: 2026-11-03. Status: accepted. Specification: [../SPEC.md](../SPEC.md).

## 1. Specification first

The format, the neuron contract and the routing rule are written down
and proved in the TypeScript core before anything else is built on them. Then a
second engine, in Rust, competes on the same conformance fixtures. The
protocol is the product; a library is one way to run it, and writing it down
first is what makes a second implementation a test instead of a fork.

## 2. Links are one-way in the network file

A link is `from -> to`. An answer goes back to the sender of the signal
automatically; automatic forwarding follows outgoing links only; two-way is two
entries. A forward that could go "backwards" along any link a neuron
has would make every answer a broadcast to its senders, and a loop by default.
The TypeScript `connect` is two-way today; the spec says how it maps (13.2).

## 3. Any replaced input cuts a running threshold call (issue #17)

When any input a threshold neuron acted on is replaced by newer work, its
running call is cut and reported as a drop. Before, only the crossing input's
replacement did, so a call could go on answering with an input that had already
been replaced, spending the most expensive work in the network on stale data.
The cost is more cut calls; the benefit is that "replaced" means the same thing
for every input.

## 4. The Rust spike may use tokio and serde_json

A later Rust engine may depend on them; its sans-IO core stays std-only, and so
do the existing Rust neurons (catalogue, music). An engine is mostly
timers, process handling and JSON; hand-writing those would be a spike
about the wrong thing. Keeping the core free of them keeps it testable on a
virtual clock, which conformance needs.

## 5. A process per neuron

Level 0 starts a process per signal; level 1 keeps one process per neuron. A
process is the boundary that lets any language join with no bindings, that
makes cancel a kill, and that makes a composed neuron sealed by construction.
It costs a spawn per signal at level 0, which is why level 1 exists. In-process
neurons are not part of the spec; a thin embedding can come later without
changing it.

## Choices made while writing the specification (open to review)

- **JSON honest rule, restated as a budget** (SPEC 3.8, AGENTS.md): 8 top-level
  fields, 6 neuron options, 2 link fields. The numbers are today's count, so
  growth is visible.
- **The producer sets the root replaces key.** The alternative, a file key that
  names a payload field, breaks the rule above. See the walk-through, finding 1.
- **Level 0 has no envelope.** Stdout is the payload; `to` and `replaces` are
  level 1. Inheritance covers the alert storm, and the simplest neuron stays
  `echo ... | program`.
- **Stdin is JSON for every payload**, a text payload being a JSON string, and a
  threshold neuron gets `{payload, inputs}`. Symmetric, testable by hand, and
  one rule. The TypeScript shell adapter differs (13.2).
- **Drops gain a `phase` field, not a new reason** (SPEC 9.3). A new reason
  value is not additive under TRACE.md's compatibility rules.
- **Staleness does not travel down a chain.** Each hop replaces on its own
  (sender, key), as in the TypeScript core today.
- **Composed neurons have `entry` and `exit`**, no `threshold`/`within`, and no
  source; the first `exit` answer is the answer.
- **Fixtures script neurons by instance path, with `when`/`after`/`reply`,** and
  compare events in order on a deterministic virtual clock. `note` events are
  compared only when asked.
