# Decision record 0001: specification version 0

Date: 2026-11-03. Status: accepted. Specification: [../SPEC.md](../SPEC.md).

## 1. Specification first

The format, the neuron contract and the routing rule are written down
and proved in the TypeScript core before anything else is built on them. Then a
second engine, in Rust, competes on the same conformance fixtures. The
protocol is the product; a library is one way to run it, and writing it down
first is what makes a second implementation a test instead of a fork.

## 2. Links are one-way in the network file

A link is `from -> to`. An answer goes back to the sender of the signal
automatically; automatic forwarding follows outgoing links only; two-way is two
entries. A forward that could go "backwards" along any link a neuron
has would make every answer a broadcast to its senders, and a loop by default.
The TypeScript `connect` is two-way today; the spec says how it maps (SPEC Appendix C).

## 3. Any replaced input cuts a running threshold call (issue #17)

When any input a threshold neuron acted on is replaced by newer work, its
running call is cut and reported as a drop. Before, only the crossing input's
replacement did, so a call could go on answering with an input that had already
been replaced, spending the most expensive work in the network on stale data.
The cost is more cut calls; the benefit is that "replaced" means the same thing
for every input.

## 4. The Rust spike may use tokio and serde_json

A later Rust engine may depend on them; its sans-IO core stays std-only, and so
do the existing Rust neurons (catalogue, music). An engine is mostly
timers, process handling and JSON; hand-writing those would be a spike
about the wrong thing. Keeping the core free of them keeps it testable on a
virtual clock, which conformance needs.

## 5. A process per neuron

Level 0 starts a process per signal; level 1 keeps one process per neuron. A
process is the boundary that lets any language join with no bindings, that
makes cancel a kill, and that makes a composed neuron sealed by construction.
It costs a spawn per signal at level 0, which is why level 1 exists. In-process
neurons are not part of the spec; a thin embedding can come later without
changing it.

## 6. Level 0 has no reply envelope

Decided 2026-11-04 by Kevin. Only level 1 may set `replaces` or `to`; a level 0
program's stdout is the payload. Inheritance of the key covers the alert storm,
and the simplest neuron stays `echo ... | program`.

## 7. The stdin shape depends on threshold above 1

Decided 2026-11-04 by Kevin, a change from the draft. A neuron gets
`{payload, inputs}` only when its `threshold` is more than 1. Threshold 1 and
plain neurons get the bare payload: with one input there is nothing to combine,
and the common case should not change shape because an option was set.

## 8. A composed neuron is one shared inner network per instance

Decided 2026-11-04 by Kevin. The inner network starts with the engine and every
call to that instance shares it, so a level 1 program inside can keep state
and each use learns on its own. Consequences, written into SPEC 2.6: each call
gets a new inner trace and inherits the outer replaces key; staleness inside is
scoped to one call, so calls cannot cut each other; slots are shared.

## 9. Junk on level 1 fails the call only if exactly one call is running

Decided 2026-11-04 by Kevin. This **departs from the brief**, which said junk
fails "that one signal". With several calls running a junk line cannot be
attributed to one, so it is only noted; guessing would fail an innocent call.

## 10. Trace header and `demo`

`library` stays a version string and an optional `engine` field names the
engine; `demo` is defined in TRACE.md as a free name. Both are v1-compatible:
the first adds an optional field, the second widens an enumeration no reader
switches on (replay never reads `demo`).

## 11. Drops get `phase`, not a new reason (issue #16)

`replaced` already covers a held input and cut running work, and the replay
summary counts `heldReplaced` as `replaced` drops minus calls cut. A new reason
value (such as `withdrawn`) is not additive: it changes what `replaced` means to
a reader that knows only the old value, and TRACE.md bumps `version` for that. An
optional `phase` (`waiting` or `running`) is ignorable. `waiting` covers both
held and queued work.

## 12. Any replaced input cuts a running threshold call (issue #17)

See decision 3 above. The drop names the crossing input, which may not itself
have been replaced.

## Defaults chosen by the builder (for review)

`timeout` 30000 ms; kill grace 2 s (SIGTERM, then SIGKILL); restart backoff
100 ms doubling to 5 s, a neuron failed after 5 consecutive failed starts;
1 MiB caps on lines and level 0 output; a program's environment is `PATH` plus
the `env` names; http redirects not followed; a `serve` neuron that cannot reach
`ready` stops the engine from starting; `description` SHOULD, not MUST; replaces
key at most 256 bytes; `maxInflight` optional, default 1; the default `within`
is not written to the trace; staleness does not travel down a chain; `exit`'s
first reply (answer or quiet) is the composed reply; the shell detectors and
other example programs use level 0 only.

## Other choices made while drafting

- Field budget: 8 top-level fields, 6 neuron options, 2 link fields (today's
  count, so growth is visible).
- The producer sets the root replaces key; a file key naming a payload field
  would break the rule.
- Stdin and stdout are JSON for every payload; a text payload is a JSON string.
- Fixtures script neurons by instance path (`when`, `after`, `reply`) and compare
  events in order on a deterministic virtual clock, in an order SPEC 6.2 fixes.
- Distribution later: the engine ships as a binary inside the npm and pip
  packages (the esbuild and ruff pattern).

## Observers

Decided 2026-11-04 (three reviewers agreed; Kevin decided the two open points).
An observer reads the live trace outside the network and cannot stop or throttle
a trace; limits live in the engine and fail closed. Without that line an observer
becomes a second, hidden router and the network file stops showing how work
flows. Timing: version 0 gets the definition and the rule; version 0.1 adds a
per-trace finished event, per-trace budget limits in the file and a normative
live trace stream, each with a fixture. No `watch` link: it would settle the
passive/active question by the back door.
