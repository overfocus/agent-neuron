# Demos

Every visible behaviour of agent-neuron has a demo here, so the ideas can be
watched and argued with, not just read. Keep this table current: a feature
that adds or changes visible behaviour adds or updates its demo and its row.

Every demo runs on the Rust engine (`rust-engine/`, the `neuron-engine` binary; the `npm run` scripts build it
first with `cargo build --release --manifest-path rust-engine/Cargo.toml`). The demos of the TypeScript library
(the first example, typing, suggest, loop, the alert storm in code, the two Rust neurons, the live network view
and the trace recorder) went with the library in [decision 0023](decisions/0023-one-engine.md); the commit
before it has them.

| Demo | Command | What it shows | Status | Open questions it informs |
|---|---|---|---|---|
| Network file | `npm run demo:network` | The alert storm with no neuron or routing code: the engine (`neuron-engine run`, started by `examples/network.mjs`) reads `spec/examples/alerts.network.json`, injects the 40 timed alerts of `alerts.inputs.jsonl`, runs the detectors as processes, forwards along links, holds `hypothesis` until two detectors agree, cuts stale calls, and runs `diagnosis` as a composed neuron. Prints a summary read from its own trace (flags, calls instead of 40, cut, replaced, expired, the last diagnosis, and that no inner id appears). `npm run demo:network -- spec/examples/alerts-python.network.json` swaps `hypothesis` for a Python program, and `-- spec/examples/alerts-python-serve.network.json` for a long-lived (level 1) Python program that handles `cancel`: the same invariants, the same event counts apart from the `term` notes. Per signal, on one machine, a level 0 Python neuron cost a process start (median 19.7 ms) and a level 1 one a pipe round trip (median 0.04 ms), against the storm's detector budget of about 150 ms (SPEC Appendix C; informative, not asserted, measured before decision 0023). The counts move with machine load, since the programs are real processes; the seven diagnoses do not. | working | Whether a network file says enough (the only caller-side piece left is the producer's keys, [decision 0002](decisions/0002-alert-storm-mapping.md)); what any other engine must match. |
| Budgets | `npm run demo:network -- spec/examples/alerts-budget.network.json` | The alert storm with a spend limit ([SPEC section 10](SPEC.md), [decision 0006](decisions/0006-budgets.md)): the same network file with a `budget` of 12 credits and a `cost` on five neurons (detectors 1, `hypothesis` 5, `diagnosis` 4). Every alert is its own trace with its own pool; the producer (`examples/network.mjs`) lowers the budget of each alert that is not critical to 6 when it injects it. The engine reserves each call's cost as it starts and commits it when the program is over, so a call the pool cannot cover is refused with an `error` of code `budget` and never starts: the summary prints what was spent, how many calls were refused and the cost that avoids, and how many traces finished `exhausted`. `finished` events carry what each trace had left. Without the lowering nothing is refused; the plain `alerts.network.json` run is unchanged but for its `finished` events. The conformance fixtures pin the rules. | working | Whether a pool per trace is the right unit for a burst of alerts (a storm of traces has no shared ceiling); whether cost belongs on the neuron or on the call; what a neuron reporting its own usage should change (not built). |
| People (human neurons) | `npm run demo:human` | A person in the loop ([decision 0008](decisions/0008-human-neurons-on-a-page.md), SPEC 3.4 and Appendix D): three invented release notes go to `rewrite`, which proposes a tighter wording as `{ draft, proposal }`, then to `editor`, a `human` neuron. The engine opens a page on 127.0.0.1 at the first question and prints its address on stderr; each note is an item showing the draft beside a word diff of the proposal, with Approve, Edit and No. Approve sends the proposal on, Edit sends your text, No is quiet. `publish`, declared `effect`, answers with what was approved, and the run prints those answers and ends when every note is answered; the page closes with it. A newer note for the same item would withdraw a waiting one. The fixtures use a scripted person (`spec/fixtures/human/`), and `rust-engine/tests/desk.rs` drives the page's API. | working | What a wait that survives a restart needs (not built); who may answer when several people can; whether a person should see the reviewers' notes (the voice pipeline, the first real user). |
| Notify (effect) | `SENT_LOG=/tmp/sent.log rust-engine/target/release/neuron-engine run spec/examples/notify.network.json --inputs spec/examples/notify.inputs.jsonl --stream notify.jsonl` | A build monitor with one side effect ([SPEC section 11](SPEC.md), [decision 0007](decisions/0007-effects-and-the-live-stream.md)): `notify` takes 300 ms to send a message about a build and is declared `effect`. Three updates arrive for one key. The second replaces the first while its message is being sent: nothing is cut, both messages go out, the first answer is recorded and not forwarded (`forwarded: false`), the second is forwarded. The third loses its connection after sending: the call is recorded as `unknown`, not an error. The stream file holds each event as it happened, and the file named by `SENT_LOG` the three messages that went out. Reconciling is the producer's part (SPEC 11.4): it injects the build id into the declared source `reconcile`, where `lookup` reads `SENT_LOG`; the fixture `observer/an-observer-reconciles-an-unknown-effect` pins it, and a live producer (`run --inputs -`) can do it by hand. Remove `effect` from the file and the first message is cut and never sent, and the crash is a plain failure a retrying producer would send again. Invented builds only. | working | Whether `unknown` should be held by the engine until reconciled (not built: a recorded event and a pattern, SPEC 11.4); what a retry policy should look like; what the outside should learn of an effect inside a composed neuron that fails after `exit` has replied (allowed since decision 0022, SPEC 11.5; that failure stays inside). |
| Team decisions | `npm run demo:team` | A team decides which of two agent-run patches lands, on real git state ([SPEC 3.4](SPEC.md) and 5.2's threshold, [decision 0008](decisions/0008-human-neurons-on-a-page.md), 11's effects): `prepare-repo.mjs` (delete, remake) builds the scratch repo at `/tmp/agent-neuron-team-demo` — a seed commit of an invented pier module (three small files) and two real branches, `agent/patch-a` and `agent/patch-b`, each a small diff in its own voice — and prints the branch graph. The candidate ask (title, why, draft, proposal, options, `answerable_by`) is injected into `review` and lands as two desk items, one each for `ic1` and `ic2`; the person answers are text, shaped by the pageserver as `<branch> \| why: <their line>`. `tally` (`threshold: 2, within`, the file-mode join of timbre's reviewers) holds the first vote and fires when both have voted, answering the direction: `{ mode: quorum, branch }` on agreement, `{ mode: tie }` on disagreement. `direction`, with no outgoing links, answers the summary as its stdout — "settled by quorum: agent/patch-a" or "tie — the lead decides" — printed live from the run's `--stream`, and the same answer is the gate item `lead` sees: on a quorum its one option's Merge button, on a tie both branches or Refuse. The lead's edit "merge <branch>" drives `apply`, declared `effect` (11: a started call is never cut, a failure records `unknown`): `merge.mjs` takes the scratch repo and the branch whitelist as argv, refuses anything else with a clear nonzero exit before any git call (no shell, no eval), runs `git merge --no-ff <branch>` and tags `team-decision` on success, its git bytes captured so stdout stays one JSON value. `budget` 12 credits (decision 0006) puts a reserve and a commit per call in the trace, with `finished.remaining`. `pageserver.mjs` (Node stdlib, one file, no CDNs, values as text) is the multiplayer desk proxy: it drives the engine desk with the x-desk-token contract and one Connection-close request per call (a pooled fetch keeps a closed desk's socket and dies on its next write), serves /p/ada and /p/lin (role ic) and /p/sam (role lead), filters each person's items by their own neuron and the payload's `answerable_by`, and keeps the shared decision ledger at /log of `{who, item, kind, text, t}` — the names live in the ledger, never in a protocol body — with a quorum line, rendered on every page. `team-demo.mjs` runs it all, prints the three person URLs and tails the engine's stderr and stream; `--headless` answers Ada then Lin (both patch-A) then Sam (merge) through the pageserver's POST path, the page's own; `--headless --tie` has Lin vote patch-B so the join sees disagreement and Sam's refusal ends it with nothing merged. Both end with the git evidence — the branch graph before, after each run the merge commit, its stat and the tag, or their absence — the full ledger, the desk answer lines of the stderr and the trace path. Invented people, invented module. | working | Who may answer when several people can (each item here is the desk's call of one named neuron, and the proxy enforces the pairing); whether a decision ledger belongs to the engine or beside it (the engine's own record is the stderr's `desk answer:` lines and the trace; the names are the demo's); what a reviewer's vote should weigh once strength exists (Appendix B). |
| Peers | `npm run demo:p2p` | Four peer engines and a driver on this machine ([decision 0013](decisions/0013-p2p.md), [P2P.md](P2P.md)): `classify` on one engine forwards to `review` on the next, whose `wrap` runs on a third and whose `audit`, a whole network, runs on a fourth. Prints where each part runs, the answer, and the trace's path. | working | What the wire between engines must carry beyond a call (cancel, `serve`, the ground, quiescence: P1 to P4). |
| Decision-surface demos | `npm run demo <name>` in [agent-neuron-demos](https://github.com/overfocus/agent-neuron-demos) | A series in its own repo, on the engine's command line with `--grants` ([decision 0010](decisions/0010-the-desk-at-a-table.md)): `quorum` (two reviewers choose, a threshold-2 join, the lead gates a real git merge), `backlog` (15 bugs, 5 requirements, 2 architecture changes for a team of three: house rules as data route lock-ins and slop to the lead, both ICs accept requirements, ADRs written either way, one fix refused by its budget), `spend` (the manager lowers the per-task ceiling on the desk, as a policy diff), `refunds` (an effect over a limit needs a person; a stale payment is not cut and not forwarded; a crash is `unknown` and reconciled), `oncall` (a newer alert withdraws the waiting ask; the late answer is refused) and `colony` (n ants as serve neurons with response thresholds, food, a nest, each ant recruiting its three nearest nestmates on finding food, dry patches that answer `emptied` and go dark on the ground, seeded drop sites — and every ant's return routed by the engine's seeded `ground` draw, the nest laying the pheromone). Each runs headless (`-- --headless`) with invented people answering through the desk's own API, and `npm test` asserts every outcome; [agent-neuron-viz](https://github.com/overfocus/agent-neuron-viz) `?attach` watches them live. Invented data only. | working | Who may answer what (grants, now built); what an async table needs (durable desk state, not built); whether presence belongs on MCP. The colony's pheromone is `ground` now (decision 0012, in-run); what stays open is the trail carrying over between runs (durable state, issue #30 item 1). |
| Conformance | `npm run conform` | Not a demo to watch: the engine run on 318 fixtures, then on the 10 probes of `spec/probes/` (a network file, scripted inputs, scripted neuron replies and scripted people on a virtual clock, exact expected events, budgets, effects, `finished` events and the live stream included). Prints pass, fail or pending per fixture and exits non-zero on a failure; the same command any other engine must offer ([CONFORMANCE.md](CONFORMANCE.md)). | working | What an engine must do exactly, and what the specification still leaves open (decision 0004). |
| Real-time search page | not built yet | A music search in a browser, as a network of neurons that each hear every keystroke, with the concerts and links neurons, results a person can click. Issue #11. | planned | Whether a click is a signal that strengthens a connection; chains inside the network (concerts listens to artist). |
