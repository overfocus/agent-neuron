# Demos

Every visible behaviour of agent-neuron has a demo here, so the ideas can be
watched and argued with, not just read. Keep this table current: a feature
that adds or changes visible behaviour adds or updates its demo and its row.

| Demo | Command | What it shows | Status | Open questions it informs |
|---|---|---|---|---|
| First example | `echo approve \| npm run example` | A shell script, a local HTTP API and a human on stdin as three neurons in one network; a waiting `send` between them. | working | Who decides where an answer goes next; what a failed neuron means for the run. |
| Typing | `npm run demo:typing` | A search box emits the query one letter at a time without waiting (`emit`). Three neurons with different latencies each decide in their own adapter whether to act. A newer prefix replaces the older one: stale work is aborted and printed as dropped. Answers carry no prefix: the demo keeps a map of what it emitted and finds each answer's prefix through `replyTo`. Made-up catalogue. | working | What a passive channel is, as opposed to an active one; whether the wrapper or the network should decide to act on an input; which answers count as useful. |
| Typing, tracks in Rust | `npm run demo:rust` | "Wrap anything" across languages: the typing demo with its tracks neuron replaced by a small Rust program (`rust/catalogue`, std only) run through the shell adapter. Same rule and catalogue as the JavaScript neuron, so the answers agree; the neuron id `tracks (rust)` shows where they come from, and stale work is still aborted and printed as dropped. Needs a Rust toolchain. | working | Whether the wrapper really is language-neutral; what crossing a process boundary costs (a spawn per signal); where a composed neuron's inner network could run in another language. |
| Composed neuron | `npm run demo:composed` | The first working composed neuron: a Rust program `music` (`rust/music`, std only) holds its own small inner network of tracks, artist and lyrics neurons, and to the TypeScript network it is one neuron through the shell adapter. The search box sends each keystroke to `music` alone; answers and stale drops print as in the other demos. The outer network sees a signal in and an answer out, with no inner ids. Then one standalone `music --inspect` run prints the inner trace (signal ids, replyTo, one trace id), labelled as the inside view. Learning is not built: each call is its own process and nothing is shared. Needs a Rust toolchain. | working | Composition; tracing across the boundary (traceable from inside only); what each use learning on its own will need (state that outlives a process). |
| Suggest (threshold) | `npm run demo:suggest` | The typing demo plus a `suggest` neuron with `threshold: 2`: the answers of tracks, artist and lyrics are forwarded to it with `{ cause }`. It holds one answer per keystroke and acts only when a second neuron answers the same keystroke; the demo prints each run with the senders that agreed, the held answers dropped as "stopped waiting: newer answer" (replaced by a newer forward) or "gave up waiting" (expired after `within`), and "suggest ran N times for M keystrokes" with a closing note on why only the last keystroke can agree. `demo:typing` is unchanged. | working | Whether agreement should weigh senders differently (strength, next); what a neuron does with the rest of a trace after it has acted. |
| Loop cut | `npm run demo:loop` | Two neurons, ping and pong, that take turns forever: an `onSignal` handler has each answerer pass its answer on to whoever it answered, with `{ cause }`, so both adapters run in turn ("start > pong > ping > pong"). Each has `maxHops: 5`; the demo prints every hop and the `onDrop(..., 'hops')` that ends the loop. Separate from the first example to keep that one a plain three-adapter tour. | working | Whether a limit per neuron is enough, or loops also need a budget per trace; who should forward answers (the caller today). |
| Alert storm | `npm run demo:alerts` | Use case 2 ([USE-CASES.md](USE-CASES.md)): 40 invented alerts for five invented services in about six seconds. An `alerts` source emits each with `replaces` keyed by service. Three cheap detectors decide for themselves: `logs` and `deploys` are POSIX sh scripts wrapped by `ShellAdapter`, `metrics` is JavaScript. Their flags are forwarded with `{ cause }` to `hypothesis` (`threshold: 2`, a fixed 500 ms standing in for a model), which runs only when two distinct detectors flag the same alert; each run counts as one expensive call. Its result goes on to `diagnosis`, a composed neuron: an adapter with its own inner network (topology lookup, read-only deploy check) that is never added to the outer one, so the outer network only ever sees one verdict. Prints one line per finished call and a summary (calls started instead of 40, how many were cut short as stale and still spent, waiting flags replaced, final diagnosis); the numbers are the same on an idle machine, and a test asserts invariants only (`test/alerts.test.ts`). Timing is chosen so ordering is stable: alerts for one service come 150 ms apart or 900+ ms apart, and a shell detector must finish within about 150 ms. | working | Whether a threshold over a trace is the right unit (a burst of alerts is several traces); whether a call cut short as stale still counts as spent; what stops the network re-diagnosing a cause it already knows (all diagnoses agree); what a composed neuron built in JavaScript costs compared with one in Rust. |
| Network view | `npm run view` | A local page (`examples/view/`, no framework, no outside requests) that draws a demo's network live while it runs: pick alerts, typing or suggest and press Run. Nodes and edges appear as the first signal touches them; markers travel along edges (a circle for a signal, a diamond for an answer), each node shows its last event in words (answer, quiet, stale, gave up, hops, acting, error) with counts of what it answered and dropped, edges thicken with traffic, quiet answers fold into one log line, a threshold neuron shows how many inputs it is "waiting" on, and a log carries every event as text. A composed neuron is one node: in the alert storm `diagnosis` appears and its inner neurons never do. The demos themselves run unchanged in the server process; the page only listens. | working | What an observer can and cannot see of a network from its traffic alone; what the graph should show once connections have a strength. |
| Trace recorder | `npm run record -- alerts` | Not a demo to watch: it runs the alerts, typing or suggest demo and writes what its network did (every signal, answer, quiet answer, drop and error, with times) to `traces/<demo>.json`, with the neurons declared up front and the demo's own summary numbers. The alert storm is recorded three times, with `hypothesis` acting at 1, 2 and 3 detectors. A small replay module folds a trace to any moment; the network view counts with the same module. Format in [TRACE.md](TRACE.md). | working | What a replayable record of a run needs to carry; whether the numbers survive a different machine (they do not: timing). |
| Network file | `npm run demo:network` | The alert storm again, with no neuron or routing code: the engine (`src/engine/`) reads `spec/examples/alerts.network.json`, injects the 40 timed alerts of `alerts.inputs.jsonl`, runs the detectors as processes, forwards along links, holds `hypothesis` until two detectors agree, cuts stale calls, and runs `diagnosis` as a composed neuron. Prints a summary read from its own trace (flags, calls instead of 40, cut, replaced, expired, the last diagnosis, and that no inner id appears). `npm run demo:network -- spec/examples/alerts-python.network.json` swaps `hypothesis` for a Python program, and `-- spec/examples/alerts-python-serve.network.json` for a long-lived (level 1) Python program that handles `cancel`: the same invariants, the same event counts apart from the `term` notes. Per signal, on one machine, a level 0 Python neuron costs a process start (median 19.7 ms) and a level 1 one a pipe round trip (median 0.04 ms), against the storm's detector budget of about 150 ms (SPEC Appendix C; informative, not asserted). The numbers match `demo:alerts`'s on an idle machine; a test asserts invariants only (`test/engine.test.ts`). | working | Whether a network file says enough (the only caller-side piece left is the producer's keys, [decision 0002](decisions/0002-alert-storm-mapping.md)); what any other engine must match. |
| Budgets | `npm run demo:network -- spec/examples/alerts-budget.network.json` | The alert storm with a spend limit ([SPEC section 10](SPEC.md), [decision 0006](decisions/0006-budgets.md)): the same network file with a `budget` of 12 credits and a `cost` on five neurons (detectors 1, `hypothesis` 5, `diagnosis` 4). Every alert is its own trace with its own pool; the producer (`examples/network.mjs`) lowers the budget of each alert that is not critical to 6 when it injects it. The engine reserves each call's cost as it starts and commits it when the program is over, so a call the pool cannot cover is refused with an `error` of code `budget` and never starts: the summary prints what was spent, how many calls were refused and the cost that avoids, and how many traces finished `exhausted`. `finished` events carry what each trace had left. Without the lowering nothing is refused; the plain `alerts.network.json` run is unchanged but for its `finished` events. A test asserts invariants only (`test/engine.test.ts`); the conformance fixtures pin the rules. | working | Whether a pool per trace is the right unit for a burst of alerts (a storm of traces has no shared ceiling); whether cost belongs on the neuron or on the call; what a neuron reporting its own usage should change (not built). |
| People (human neurons) | `npm run demo:human` | A person in the loop ([decision 0008](decisions/0008-human-neurons-on-a-page.md), SPEC 3.4 and Appendix D): three invented release notes go to `rewrite`, which proposes a tighter wording as `{ draft, proposal }`, then to `editor`, a `human` neuron. The engine opens a page on 127.0.0.1 at the first question and prints its address on stderr; each note is an item showing the draft beside a word diff of the proposal, with Approve, Edit and No. Approve sends the proposal on, Edit sends your text, No is quiet. `publish`, declared `effect`, answers with what was approved, and the run prints those answers and ends when every note is answered; the page closes with it. A newer note for the same item would withdraw a waiting one. Tests use a scripted person for the engine (`test/human.test.ts`) and drive the page's gate (`test/page.test.ts`). | working | What a wait that survives a restart needs (not built); who may answer when several people can; whether a person should see the reviewers' notes (the voice pipeline, the first real user). |
| Notify (effect) | `npm run demo:notify` | A build monitor with one side effect ([SPEC section 11](SPEC.md), [decision 0007](decisions/0007-effects-and-the-live-stream.md)): `notify` takes 300 ms to send a message about a build and is declared `effect`. Three updates arrive for one key. The second replaces the first while its message is being sent: nothing is cut, both messages go out, the first answer is recorded and not forwarded (`forwarded: false`), the second is forwarded. The third loses its connection after sending: the call is recorded as `unknown`, not an error, and the producer's observer injects the build id into the declared source `reconcile`, where `lookup` finds that the message was sent. The live stream prints each event as it happens. Then the same network runs with `effect` removed: the first message is cut and never sent, and the crash is a plain failure a retrying producer would send again. Invented builds only. A test asserts invariants (`test/engine.test.ts`). | working | Whether `unknown` should be held by the engine until reconciled (not built: a recorded event and a pattern, SPEC 11.4); what a retry policy should look like; whether an effect belongs inside a composed neuron (not allowed, SPEC 11.5). |
| Team decisions | `npm run demo:team` | A team decides which of two agent-run patches lands, on real git state ([SPEC 3.4](SPEC.md) and 5.2's threshold, [decision 0008](decisions/0008-human-neurons-on-a-page.md), 11's effects): `prepare-repo.mjs` (delete, remake) builds the scratch repo at `/tmp/agent-neuron-team-demo` — a seed commit of an invented pier module (three small files) and two real branches, `agent/patch-a` and `agent/patch-b`, each a small diff in its own voice — and prints the branch graph. The candidate ask (title, why, draft, proposal, options, `answerable_by`) is injected into `review` and lands as two desk items, one each for `ic1` and `ic2`; the person answers are text, shaped by the pageserver as `<branch> \| why: <their line>`. `tally` (`threshold: 2, within`, the file-mode join of timbre's reviewers) holds the first vote and fires when both have voted, answering the direction: `{ mode: quorum, branch }` on agreement, `{ mode: tie }` on disagreement. `direction`, with no outgoing links, answers the summary as its stdout — "settled by quorum: agent/patch-a" or "tie — the lead decides" — printed live from the run's `--stream`, and the same answer is the gate item `lead` sees: on a quorum its one option's Merge button, on a tie both branches or Refuse. The lead's edit "merge <branch>" drives `apply`, declared `effect` (11: a started call is never cut, a failure records `unknown`): `merge.mjs` takes the scratch repo and the branch whitelist as argv, refuses anything else with a clear nonzero exit before any git call (no shell, no eval), runs `git merge --no-ff <branch>` and tags `team-decision` on success, its git bytes captured so stdout stays one JSON value. `budget` 12 credits (decision 0006) puts a reserve and a commit per call in the trace, with `finished.remaining`. `pageserver.mjs` (Node stdlib, one file, no CDNs, values as text) is the multiplayer desk proxy: it drives the engine desk with the x-desk-token contract and one Connection-close request per call (a pooled fetch keeps a closed desk's socket and dies on its next write), serves /p/ada and /p/lin (role ic) and /p/sam (role lead), filters each person's items by their own neuron and the payload's `answerable_by`, and keeps the shared decision ledger at /log of `{who, item, kind, text, t}` — the names live in the ledger, never in a protocol body — with a quorum line, rendered on every page. `team-demo.mjs` runs it all, prints the three person URLs and tails the engine's stderr and stream; `--headless` answers Ada then Lin (both patch-A) then Sam (merge) through the pageserver's POST path, the page's own; `--headless --tie` has Lin vote patch-B so the join sees disagreement and Sam's refusal ends it with nothing merged. Both end with the git evidence — the branch graph before, after each run the merge commit, its stat and the tag, or their absence — the full ledger, the desk answer lines of the stderr and the trace path. Invented people, invented module. | working | Who may answer when several people can (each item here is the desk's call of one named neuron, and the proxy enforces the pairing); whether a decision ledger belongs to the engine or beside it (the engine's own record is the stderr's `desk answer:` lines and the trace; the names are the demo's); what a reviewer's vote should weigh once strength exists (Appendix B). |
| Decision-surface demos | `npm run demo <name>` in [agent-neuron-demos](https://github.com/overfocus/agent-neuron-demos) | A series in its own repo, on the engine's command line with `--grants` ([decision 0010](decisions/0010-the-desk-at-a-table.md)): `quorum` (two reviewers choose, a threshold-2 join, the lead gates a real git merge), `backlog` (15 bugs, 5 requirements, 2 architecture changes for a team of three: house rules as data route lock-ins and slop to the lead, both ICs accept requirements, ADRs written either way, one fix refused by its budget), `spend` (the manager lowers the per-task ceiling on the desk, as a policy diff), `refunds` (an effect over a limit needs a person; a stale payment is not cut and not forwarded; a crash is `unknown` and reconciled), `oncall` (a newer alert withdraws the waiting ask; the late answer is refused) and `colony` (n ants as serve neurons with response thresholds, food neurons, a nest that alone writes the pheromone). Each runs headless (`-- --headless`) with invented people answering through the desk's own API, and `npm test` asserts every outcome; [agent-neuron-viz](https://github.com/overfocus/agent-neuron-viz) `?attach` watches them live. Invented data only. | working | Who may answer what (grants, now built); what an async table needs (durable desk state, not built); whether presence belongs on MCP; whether the colony's pheromone is the adaptive link layer of Appendix B. |
| Conformance | `npm run engine -- conform spec/fixtures` | Not a demo to watch: the engine run on 203 fixtures (a network file, scripted inputs, scripted neuron replies and scripted people on a virtual clock, exact expected events, budgets, effects, `finished` events and the live stream included). Prints pass, fail or pending per fixture and exits non-zero on a failure; the same command any other engine must offer ([CONFORMANCE.md](CONFORMANCE.md)). | working | What an engine must do exactly, and what the specification still leaves open (decision 0004). |
| Real-time search page | not built yet | The same music search in a browser, with the concerts and links neurons, results a person can click. Issue #11. | planned | Whether a click is a signal that strengthens a connection; chains inside the network (concerts listens to artist). |
